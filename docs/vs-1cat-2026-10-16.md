## Concurrency=2 (8K prompt, gen 128, speed_bench)
Original workload uses per-stream seeds → prompts diverge at token 3 (inside KV block 0), so no content-addressed reuse is possible for ANY engine (1cat radix tree included). The old "decode sum" metric (-22%) was an artifact: 1cat delays both TTFTs to ~7s then pure-decodes (higher per-stream averages); ninfer serves the first stream at ttft 3.6s and its decode average is diluted by the mixed units while the second stream prefills. Equal end-to-end wall; ninfer better first-stream TTFT. Gap CLOSED.

| divergent prompts | 1cat | ninfer v1 |
|--|--|--|
| stream A ttft / decode | 6.70 / 37.4 | **3.57 / 20.2\*** |
| stream B ttft / decode | 7.39 / 46.2 | 7.12 / 45.0 |
| wall (both done) | ~10.1s | 9.96 / 10.00s (**par**) |

\* pure decode is 44-45 tok/s; the average is diluted by the ~3.5s window where the other stream's 8192-token prefill chunk shares the mixed unit (1 decode token per chunk).

Shared-prefix variant (identical seed; 2026-10-16 14:09 run): ninfer reuses the STILL-RUNNING lane's KV via block snapshot (`cache=7360 reuse=block_snapshot`), second prefill 3.5s→~0.2s; both streams ttft ~3.6-3.8, decode ~45, **wall 6.6s** (vs 10.0s divergent). Cross-lane borrow from a running lane works (borrow_prefix, pages immutable after commit).

## Notes
- Cold prefill win driven by NINFER_SM70_PREFILL_GEMM=1 (cuBLAS prefill GEMMs, dequant shared): GEMMs were 72% of prefill; cuBLAS is 18-27% faster than CUTLASS on these shapes.
- cuBLAS route pitfalls fixed in 6b21975c: per-device handles (interleaved TP2 single-thread), w is out-major [n][k] (need transa=T, lda=k), SM70 rejects CUDA_R_16BF out (fp16 scratch + convert).
- 1cat run once per config is enough (stddev <1%).
- speed_bench prefill/ttft segments share prompt prefixes across sizes (not fully cold) — use bench_prefill_cold.py for cold claims.
